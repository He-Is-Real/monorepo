# Tooling and accounts

Every command-line tool and third-party account the project uses, what it's for here, and how a
developer gets it. Procedures live in the files this page links to; this page says what you need
and where to look. Joel (founder) administers every account and gives access by invitation.

Last checked: 2026-10-25.

## New developer checklist

From a fresh machine to `pnpm nx run-many -t lint test build typecheck` and a local OpenTofu plan:

1. **Accounts:** ask Joel for a GitHub invite to the `He-Is-Real` organisation (team
   `developers`) and a `@heisreal.today` Google identity. The organisation only accepts
   `heisreal.today` identities in GCP (`infra/terraform/README.md`, "Lessons learned").
2. **Git:** set up a GPG signing key and add it to GitHub; `main` only accepts signed commits
   (ruleset `protect-main`). Use your GitHub noreply address as the repo's `user.email`.
3. **Clone** `He-Is-Real/monorepo` and install [mise](https://mise.jdx.dev). In the clone run
   `mise install` (OpenTofu, gitleaks, kubeconform from `mise.toml`), then
   `tools/scripts/install-hooks.sh` (the gitleaks pre-commit hook, once per clone).
4. **Node 24 and pnpm 11** (`.nvmrc`, `packageManager` in `package.json`), then `pnpm install`.
5. **Build and test:** `pnpm nx run-many -t lint test build typecheck`. The integration tests
   (`pnpm nx run database:test-integration` and friends) also need Docker and `python3` on your
   `PATH` (see the table); the e2e suite needs `pnpm exec playwright install chromium`
   ([README](../README.md), "Getting started").
6. **GCP access:** Joel adds you to `developers` in `infra/terraform/live/dev/bootstrap/main.tf`
   and applies `bootstrap` (project Owner on `heisreal-dev`, Token Creator on `tf-deployer` and
   `tf-bunny`, the `tofu-state` and `tofu-bunny` keys). Then install gcloud and run
   `gcloud auth login --update-adc`.
7. **A local plan:** `tools/scripts/tf.sh gcp init` then `tools/scripts/tf.sh gcp plan`
   ([infra/terraform/README.md](../infra/terraform/README.md), "Day to day").

The rest (kubectl, the Clerk, Bunny and Resend CLIs, ffmpeg) only matters for the tasks listed
against each below.

**gcloud and ADC.** `--update-adc` writes Application Default Credentials too, which the apps,
OpenTofu and `tf.sh` impersonation use. The Google Workspace forces re-authentication now and then;
run the same command again. `tf.sh` needs Token Creator on `tf-deployer` / `tf-bunny` (from the
`developers` list); `TF_SH_IDENTITY=self` runs as you instead. The local `images` root also needs
the plain `gcloud auth login` session. Applying `bootstrap` needs
`GOOGLE_BILLING_PROJECT=heisreal-dev USER_PROJECT_OVERRIDE=true` (`infra/terraform/README.md`,
"Lessons learned").

**kubectl on GKE.** `get-credentials` needs `gke-gcloud-auth-plugin`
(`gcloud components install gke-gcloud-auth-plugin`, or your distribution's package). Without it,
pass a token yourself for read-only commands:
`kubectl --token="$(gcloud auth application-default print-access-token)" …`.

**Resend CLI key storage.** `resend login` uses secure storage when it can (on Linux, the Secret
Service through `secret-tool`); when it can't, it silently writes the key in plain text to
`~/.config/resend/credentials.json`, even without `--insecure-storage`. On Linux, first install
`secret-tool` (`libsecret`, or `libsecret-tools` on Debian/Ubuntu) and run a Secret Service
provider such as gnome-keyring or KeePassXC. After logging in, `resend login` says either
"stored … in Secret Service (libsecret)" or "stored … at <path>" with a tip to install
libsecret. To check without printing the key:
`jq '{storage, profiles: (.profiles | map_values(keys))}' ~/.config/resend/credentials.json`
must show `"storage": "secure_storage"` and no `api_key` field in the profile. If it shows
`"file"` or an `api_key` field, run `resend logout`, fix the Secret Service and log in again.

**Optional AI tools.** PRs are built and reviewed with Claude Code and the Codex CLI (Joel's global
mise: `claude`, `codex`). The review briefs live outside this repo. Neither is needed to build,
test or contribute.

**In CI** `python3` comes preinstalled on the `ubuntu-latest` runner image (no workflow sets it
up), as do Docker and kind. The workflows install the same OpenTofu, gitleaks and kubeconform versions, pinned
separately and kept in step with `mise.toml` (`ci.yml`, `.github/actions/tofu`); Node from
`.nvmrc`, pnpm from `package.json`, and Playwright's Chromium from the Actions cache
([README](../README.md), "Cloud and CI").

### M2 prerequisites and notes from 0.8 (2026-10-21, #41)

Decided while reviewing #41 (the coordinator's calls; Joel can overrule):

- **Prerequisite: wire D39 erasure to Art 9 withdrawal before accepting real testimonies** (a gate
  for the Real stories phase, D46). Since
  0.8, withdrawing `special_category_religious` records the event and unpublishes the person's
  stories, and the database then refuses every further processing step. The stories stay stored
  until erasure is built.
- **Consent checkbox wording gets versioned** (with the DPA text in `libs/legal`) and added to the
  evidence hash (`heisreal-consent-evidence/v2`) in M2's consent form. Today the hash covers the
  DPA version, its text's sha256, the type, event and mechanism.
- **The legacy consent type is named `legacy_migration`** in task 1.9 (D44 wrote
  `legacy-migration`; every other consent value is snake_case). Task 1.9 and D44's legacy import
  move to the Real stories phase (D46).
- **Uploads keep the prototype's lightweight presigned flow** (with the client-direct uploads
  row below). api-user creates the Bunny Stream video with the library key and returns
  `libraryId`, `videoId`, `expirationTime` and `presignedSignature`, which is the sha256 of
  libraryId + libraryKey + expirationTime + videoId. The client uploads straight to Bunny by TUS;
  the API never handles media bytes. Field names change only for naming conventions. The

#### Joel's decisions of 2026-10-23 (M1 follow-ups to #57)

- **A2: approval is blocked until media processing is complete.** "If there is a malicious upload we
  don't want this to go by; we also don't want to release unprocessed content to the public view."
  Every video, audio file and image must be processed (`ready`) before approval, with its facts:
  a video's width, height and duration, an audio file's duration. Only processing (workflow, M7)
  sets the state; a changed upload starts again. Approved videos therefore always have a size, so
  cards no longer need a square fallback for them (`cardAspect` keeps it for unknown sizes).
- **A3: the POC's story text limit.** A story's text is at most 10,000 characters (was 20,000).
  Long written stories show about the first 600 characters, cut at a word, with a "Continue
  reading" button that expands the text in place ("Show less" collapses it).
- **A3b: the POC's minimum for written stories.** A written story needs at least 200 characters
  (trimmed) to be submitted; drafts can be shorter. Video and audio text has no minimum.
- **An approved story isn't reverted when its media breaks.** "A story should not revert after
  once it has approval - that means we need to do something with bunny support and get it
  loading again instead of approving again." While any of its media isn't ready (failed, being
  checked again, or missing its size or duration), the story stays `approved` but is hidden from
  the public read model, in the same write. When the same media is ready again, it is published
  again on its own, with no new approval. History records both; admins can list hidden stories.
  Runbook: [media-runbook.md](media-runbook.md). Details: [db-permissions.md](db-permissions.md)
  item 27.
- **A superseded OpenTofu apply run shows a warning, not a green tick.** The run warns
  "Superseded by run N: nothing applied; the newer run plans main HEAD." and ends red, so it
  can't look like a deploy (`tofu-apply.yml`, job `superseded`).
- **NestJS 12 (ESM): upgrade when sensible; recommended after M1.** Recorded against the open
  Dependabot issue #5; not upgraded yet.

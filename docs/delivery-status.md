  story is unpublished. Fine for dummy data. Before Real stories: a shorter expiry, or rotating the

  Stream thumbnails and images use Bunny's Advanced CDN token (HMAC-SHA256). Basic (MD5) tokens
  are deprecated by Bunny. One key signs both Stream kinds: the Stream pull zone's.
- **Only what's safe is signed:** video ids must look like Bunny's (UUIDs), paths may use only
  `A-Z a-z 0-9 . _ -` and `/` (no `..`), and a thumbnail only inside its own video's folder.
  Anything else gets `null`.

#### Notes from step 6b-2 (static pages, SEO, cookies)

Coordinator's calls in this step (not yet numbered as decisions; Joel can overrule):

- **Indexing is an explicit opt-in, fenced from dev (#65 review).** web is noindex (header,
  meta tag), `robots.txt` is `Disallow: /` with no `Sitemap:` line and `/sitemap.xml` is `404`
  unless `INDEXING=allow` exactly **and** a valid `SITE_URL`; a missing or misspelled value
  fails closed. OpenTofu: `web_indexing` (default off) is refused when the project is
  `heisreal-dev` and needs `web_site_url` (tftests). It replaces `web_noindex`; Cloud Run still
  gets `ROBOTS_NOINDEX` (from `web_indexing`) for images built before #65, to be removed later.
  Go live: `web_site_url` = the real domain and `web_indexing = true`. A crawler that obeys
  `Disallow: /` never sees the `noindex`, so a URL linked from elsewhere could still be listed
  without content; acceptable for dev.
- **`SITE_URL`** (`web_site_url`: an https DNS origin, no IP, port or path; dev = web's `run.app`
  URL) is the only source of absolute URLs (canonical, og:url, images, JSON-LD, sitemap), never
  the request (D32). Without it, no URL-bearing metadata is emitted at all. web's `siteUrl()`
  accepts everything OpenTofu does, and logs and ignores a malformed value rather than failing
  pages. Every page builds its metadata per request through `pageMetadata()` (own canonical;
  the root layout sets none).
- **Sitemap budget (#65 review):** `no-store` like all story data (D51); one walk shared by
  concurrent requests (single flight, dropped when it settles); a 20 s overall deadline that
  aborts the API call in flight, at most 1,000 pages, stop at an empty page, refuse a repeated
  cursor; a closed request stops waiting, and when all have gone the walk is aborted. Over budget
  or API down: `503` with `Retry-After`, never a partial sitemap. Capped at 50,000 URLs.
- **No cookie banner (PECR, UK GDPR).** What the site stores, checked in a real (non-automated)
  browser on 2026-10-23: `theme` in localStorage (only after the visitor picks a theme); Clerk
  on every page through the header (D32): `__client_uat` (set for signed-out visitors too),
  `__session` when signed in, `__clerk_db_jwt` (development instances only),
  `__clerk_environment` in localStorage, and Cloudflare's `__cf_bm`/`_cfuvid` on Clerk's domain
  (bot protection). **Clerk's product telemetry is off** (`telemetry={false}`): it was sending
  events to clerk-telemetry.com and storing `clerk_telemetry_throttler` (optional, so not
  strictly necessary). Clerk skips telemetry for automated browsers (`navigator.webdriver`), so

  cookies and stores nothing during default playback; once the visitor changes the playback

Notes on the M2 decisions (from `m2-decisions.html`):

- **D68, the upload recipe.** Images go to the storage zone's S3 endpoint with a SigV4 presigned
  PUT that api-user signs for a few minutes. It binds the object key (api-user picks it),
  `Content-Type`, `Content-Length` and the expiry: a wrong type, size or key, or an expired link,
  answers 403, and overwriting an existing image can be refused (412). Video and audio use the
  prototype's TUS signature (0.8 notes above), which binds only the video and the expiry: a wrong
  or expired signature answers 401/400, and audio files are accepted. Designed around: video size
  and type are known only after upload, from Bunny's encoding result (junk ends as "failed",
  refused at submit); an unexpired TUS signature can replace the file, so signatures last about
  an hour and an "encoding finished" notice after approval counts as changed media (D59: approve
  again); an image's type is what the browser declares, so processing checks the real content
  before it's ready; Bunny's S3 API is a preview whose CORS differs from its docs, so M2 adds a
  test that catches a change. M2's upload PRs document the exact signing code.
- **D78, the M2 flow.** Bunny's "encoding finished" notice reaches api-user, which publishes it
  to Pub/Sub; a Dapr worker on Joel's machine pulls it, reads the video's real facts from Bunny
  and publishes the result to a results topic; the private Cloud Run result writer marks the
  video ready (D76). Subscriptions keep messages for 31 days, with a catch-up sweep for stuck
  work; Dapr Workflow's progress is on that machine's disk. The church machine signs in to Google
  keylessly (Workload Identity Federation, through OpenTofu). In dev a video story can be approved
  only once the machine has run since the upload. With real data, the machine needs disk
  encryption and physical security, and the privacy document must say where processing happens.
- **D84, the columns.** `signupFormVersion`: version, status (draft, published, retired; frozen
  once published), `textRef` and `textHash`, `dpaVersion`, `publishedAt`. `testimonyFormVersion`:
  the same, plus `requiresReconsent`, `coversPublicPublishing`, `draftRetentionMonths` (D71) and
  one column per platform (`shareYouTube`, `shareInstagram`, `shareTikTok`, `shareFacebook`, …).
  Before a story is posted to a platform, the column in its uploader's current testimony form
  (D86: stories store no version) and the person's optional "share on social media" tick are both
  checked. 18+ is wording on every version of both forms, not a column.
- **D85 and D86, what changes in M2.** The story's `consent` field and the `StoryConsent` object
  in the story responses go; the database and API checks follow `story.submitter` to the person's
  latest consent events instead. New testimony-form wording must say plainly that it covers
  stories already submitted, because accepting it widens sharing for those too.
- **D87, the order.** M1–M8, Real stories, Go live (with the domain transfer), then Emails.
  Assumed: Go live may put the site up first, but new public submissions open only once emails
  work, so nobody submits a testimony without a confirmation. The 24 imported testimonies in Real
  stories need no emails.

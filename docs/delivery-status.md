#### Notes from step 5 (media token auth, D52)

- **Expiry: 6–7 hours.** Links outlive any cached response (60 s + 300 s today, D52) and a page

  older link than the API gave it. The expiry is rounded up to the hour, so a story's body and
  ETag change at most hourly and `304`s still work.
- **Withdrawal:** links already handed out keep working until they expire, up to 7 hours after a
  story is unpublished. Fine for dummy data. Before Real stories: a shorter expiry, or rotating the
  key on withdrawal (it cuts off every link at once), with D51's production purge. Decided: D64.
- **Tokens:** Stream player links use Bunny's embed token (sha256 of key, video id, expiry);
  Stream thumbnails and images use Bunny's Advanced CDN token (HMAC-SHA256). Basic (MD5) tokens
  are deprecated by Bunny. One key signs both Stream kinds: the Stream pull zone's.
- **Only what's safe is signed:** video ids must look like Bunny's (UUIDs), paths may use only
  `A-Z a-z 0-9 . _ -` and `/` (no `..`), and a thumbnail only inside its own video's folder.
  Anything else gets `null`.
- **M2 prerequisite:** api-user must set `bunnyVideoId`, `thumbnailPath` and `image.path` itself
  (from its own upload targets, under a story-specific prefix), never from the client. Otherwise a

- **Touch targets in Bunny's player:** its controls are 34–38 px by default. CSS in the library's

#### Notes from step 6b-2 (static pages, SEO, cookies)

Coordinator's calls in this step (not yet numbered as decisions; Joel can overrule):

- **Indexing is an explicit opt-in, fenced from dev (#65 review).** web is noindex (header,
  meta tag), `robots.txt` is `Disallow: /` with no `Sitemap:` line and `/sitemap.xml` is `404`

  Go live: `web_site_url` = the real domain and `web_indexing = true`. A crawler that obeys
  `Disallow: /` never sees the `noindex`, so a URL linked from elsewhere could still be listed
  without content; acceptable for dev.
- **`SITE_URL`** (`web_site_url`: an https DNS origin, no IP, port or path; dev = web's `run.app`
  URL) is the only source of absolute URLs (canonical, og:url, images, JSON-LD, sitemap), never
  the request (D32). Without it, no URL-bearing metadata is emitted at all. web's `siteUrl()`
  accepts everything OpenTofu does, and logs and ignores a malformed value rather than failing
  pages. Every page builds its metadata per request through `pageMetadata()` (own canonical;
  the root layout sets none).
- **Sitemap budget (#65 review):** `no-store` like all story data (D51); one walk shared by
  concurrent requests (single flight, dropped when it settles); a 20 s overall deadline that
  aborts the API call in flight, at most 1,000 pages, stop at an empty page, refuse a repeated
  cursor; a closed request stops waiting, and when all have gone the walk is aborted. Over budget
  or API down: `503` with `Retry-After`, never a partial sitemap. Capped at 50,000 URLs.
- **No cookie banner (PECR, UK GDPR).** What the site stores, checked in a real (non-automated)
  browser on 2026-10-23: `theme` in localStorage (only after the visitor picks a theme); Clerk
  on every page through the header (D32): `__client_uat` (set for signed-out visitors too),
  `__session` when signed in, `__clerk_db_jwt` (development instances only),
  `__clerk_environment` in localStorage, and Cloudflare's `__cf_bm`/`_cfuvid` on Clerk's domain
  (bot protection). **Clerk's product telemetry is off** (`telemetry={false}`): it was sending
  events to clerk-telemetry.com and storing `clerk_telemetry_throttler` (optional, so not
  strictly necessary). Clerk skips telemetry for automated browsers (`navigator.webdriver`), so
  the e2e check poses as an ordinary Chrome. Bunny's player (signed playback started) sets no
  cookies and stores nothing during default playback; once the visitor changes the playback
  speed, volume or mute, it keeps them in `bunny_stream_settings_<library id>` in its frame's
  localStorage (player.mediadelivery.net) until cleared: a preference the visitor sets, so
  strictly necessary like `theme` (Codex round 2; checked by the dev behavioural suite,
  `media.behaviour.ts`). While playing it POSTs playback statistics (video, seconds watched, a
  per-load session id) to `video.bunnycdn.com`: no device storage, so not a PECR matter, but

#### Joel's decisions of 2026-10-23 (M1 follow-ups to #57)

- **Joel, 2026-10-23: no featured or pinned stories — unfair to everyone else; home shows newest
  stories** (A4 below). Nothing picks one person's story over the others: no `FEATURED_STORY_SLUG` (removed

- **A2: approval is blocked until media processing is complete.** "If there is a malicious upload we

  reading" button that expands the text in place ("Show less" collapses it).
- **A3b: the POC's minimum for written stories.** A written story needs at least 200 characters
  (trimmed) to be submitted; drafts can be shorter. Video and audio text has no minimum.
- **An approved story isn't reverted when its media breaks.** "A story should not revert after
  once it has approval - that means we need to do something with bunny support and get it
  loading again instead of approving again." While any of its media isn't ready (failed, being
  checked again, or missing its size or duration), the story stays `approved` but is hidden from
  the public read model, in the same write. When the same media is ready again, it is published
  again on its own, with no new approval. History records both; admins can list hidden stories.
  Runbook: [media-runbook.md](media-runbook.md). Details: [db-permissions.md](db-permissions.md)
  item 27.

  "Superseded by run N: nothing applied; the newer run plans main HEAD." and ends red, so it
  can't look like a deploy (`tofu-apply.yml`, job `superseded`).

  Dependabot issue #5; not upgraded yet.

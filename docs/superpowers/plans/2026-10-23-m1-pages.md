# M1 step 6b-1: home, browse and story pages — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** web gets the M1 public pages (plan tasks 1.1–1.4): home, browse with balanced masonry
(D55), and the video/audio and written story pages with share and related stories, from the
mockups, on api-public-read's step 6a API.

**Architecture:** Server components render every page from api-public-read (D32). Browse is
server-rendered for the URL's filters and page count; a small client island loads more pages
through a server action (still server-side to the API) and keeps the count in the URL. The
masonry is a CSS grid with `grid-auto-flow: dense`: each card has a column and a row span per
column count, computed from predicted heights on the server (D55) and corrected from measured
heights in the browser. Cards stay in date order in the DOM.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4 tokens in `global.css`, Radix
Popover (already a dependency) for share, Jest + Testing Library, Playwright device matrix.

**Spec:** the 6b-1 brief; mockups `project/context/future/design/public/{home,browse,story-video,story-written}.html`,
`styles.css`, `accessibility-audit.md`; `project/context/future/content/{home,browse,story-pages}.md`;
`design-principles.md`; delivery plan 1.1–1.4; D53 and D55 (`m1-dev-data-decisions.html`).

## Global Constraints

- Decisions in the monorepo win over mockups; each deviation goes in the PR.
- No totals or counts from the API (api-conventions); no engagement metrics; no auto-play.
- D55: at most 2 automatic extra pages, then a "Show more stories" button; an end message.
- D32: api-public-read only, server-side only, nothing from the visitor's request (the lint
  rules forbid `next/headers`, `.headers`, `.cookies`).
- No third-party scripts, SDKs or trackers. Share links are plain URLs. No inline event
  handlers. No Apple-specific tech.
- Responsive 320 px → 2560 px: no horizontal scroll, 44 px targets, `max-w-prose` lines,
  safe areas; light and dark; visible focus; reduced motion.
- Copy: plain short sentences, warm, no preaching, no pressure.
- New pages covered in `apps/web/e2e` across `devices.ts`, both schemes.

## Design decisions (my calls)

- **Routes:** browse is `/stories` (`/browse` permanently redirects there); stories stay
  `/stories/[slug]`. Nav links point at the static pages' routes from the mockups (`/about`,
  `/faqs`, `/greatest-story`, `/contact`, `/get-ready`, `/next-steps`), built by step 6b-2.
  "Share your story" → `/get-ready` (submission is M2). Donate → `/donate`, a one-paragraph
  placeholder page (M4) unless 6b-2 builds it.
- **Masonry columns:** 1 column below 640 px, 2 from 640, 3 from 1024, 4 from 1536. Row unit
  4 px, column gap 24 px; the vertical gap is folded into each card's span.
- **Height prediction** (`lib/masonry.ts`): body padding + title lines + excerpt lines (max 3,
  line-clamped) + tag row + meta row + media height (card width ÷ `cardAspect`, audio band 2:1,
  written without image: none). Text lines = ceil(chars × average glyph width ÷ text width),
  average glyph width 0.5 em for DM Sans. No pretext dependency: the browser measures the real
  cards instead (exact, and nothing new to install). Deviation from D55's wording, noted.
- **Placement:** each card into the currently shortest column, computed per column count on the
  server and emitted as CSS variables (`--c1..--c4`, `--s1..--s4`); media queries pick them.
  New pages continue from the current column heights; cards on screen never change column. After
  hydration a `ResizeObserver` sets each card's span to its measured height.
- **Pages:** 15 cards per page (D55's "about 45" over 3 pages). URL `?pages=N` (1–10) restores
  what was loaded on Back/reload: the server fetches N pages. Auto-loads used = min(N − 1, 2).
- **Load more:** a server action `loadMoreStories(filters, cursor)` validates its input and calls
  `browseStories`. An `IntersectionObserver` sentinel 800 px before the end triggers auto-loads.
  After 2: "You've seen N stories." + "Show more stories". At the end: "You've seen every story
  here." New cards are announced in a polite live region. Errors show "Stories couldn't load.
  Try again." with a retry button.
- **Filters:** one GET form (works without JS): search (labelled), sort (Latest first, Oldest
  first; "Best match" too when there's a search), format (All, Video, Audio, Written), and a
  Search button. Tags are links that toggle a tag in the URL (all-of, max 5); "All" clears them.
  Theme tags show first; journey and emotion tags sit behind a "More tags" disclosure
  (`<details>`), open when one of them is selected. Shown above the grid: "Stories tagged
  Healing" / "Results for "…"", never a count.
- **Cards:** video (signed thumbnail at its clamped shape, play glyph, duration badge), audio
  (2:1 band with the byline's initial, "Audio · 0:12"), written with image (image, "Written ·
  N min read"), written without image (no media; the excerpt as a larger quote). Home uses the
  same card with a uniform 16:10 media box.
- **Home:** hero (mockup copy; a brand background: the backdrop photo waits for its licence, 2026-10-24), the 3 newest stories ("Recently shared"; no featured or pinned story, Joel 2026-10-23); explore tracks from
  `GET /v1/tags` (theme = "Going through something?", journey = "Curious about faith?") without
  the mockup's taglines (they quote real testimonies); "Your story" CTA; no impact strip until there are real figures (2026-10-24); donate section linking to
  `/donate`.
- **Story page:** breadcrumb (Stories › first tag › title), player or image, share, title,
  "Shared 12 March 2026 · byline", tag links, then text (+ pull quote: the description, for
  written stories) beside a sidebar: related (3 from `/related`) and "Does this resonate?" →
  `/next-steps`. Favourite, "This helped me" and Concern are M2+: left out.
- **Share:** Radix Popover; WhatsApp `https://wa.me/?text=`, Facebook
  `https://www.facebook.com/sharer/sharer.php?u=`, X `https://x.com/intent/post?url=&text=`,
  Instagram (no share URL exists: copies the link and says "Link copied. Paste it in
  Instagram."), Copy link. URLs built from `window.location` in the browser.
- **Open Graph:** through step 6b-2's `pageMetadata` (`lib/seo.ts`, which owns `SITE_URL`,
  `metadataBase` and canonicals): `og:type article`, `publishedTime`, tags, and 6b-2's default
  brand card (`/og-default.png`). Signed thumbnails expire in 6–7 h (D52), while share previews
  are cached far longer. Plus a schema.org `Article` through 6b-2's `jsonLdScript`.

## Review Focus

- Filters with no results (and a tag slug that doesn't exist): a calm empty state, not an error.
- A cursor from different filters (the API answers 400): the load-more action shows the retry
  message; it never crashes the page.
- `?pages=` garbage (0, 99, "x"): clamped to 1..10.
- Keyboard: tag links, filters, cards, Show more and share are all reachable in order; Escape
  closes share and returns focus to its button.
- 320 px with 5 long tags on a card, long titles and long words: no horizontal scroll.

### Task 1: Masonry prediction and placement (`lib/masonry.ts`)

**Files:** Create `apps/web/src/lib/masonry.ts`, `apps/web/src/lib/masonry.spec.ts`

**Interfaces — Produces:**

- `COLUMN_COUNTS = [1, 2, 3, 4] as const`; `ROW_UNIT = 4`; `GAP = 24`
- `type CardShape = { kind: 'video'|'audio'|'written'; aspect: number | null; titleChars: number; excerptChars: number; tagCount: number }`
- `cardShape(s: StorySummary): CardShape`
- `predictHeight(shape: CardShape, cardWidth: number): number` (px)
- `columnWidth(columns: number): number` (representative card width per column count)
- `place(heights: number[], columns: number, start?: number[]): { column: number[]; heights: number[] }` — shortest column, ties to the leftmost; `start` = current column heights
- `spanFor(heightPx: number): number` = ceil((height + GAP) / ROW_UNIT)
- `layoutFor(cards: StorySummary[], start?: Record<number, number[]>): CardLayout[]` with `CardLayout = { col: Record<number, number>; span: Record<number, number> }`, plus the end column heights

- [ ] Tests: written-without-image is shorter than written-with-image; a 9:16 video is taller than a 16:9 one at the same width; aspects clamp at 9:16 and 2:1 (a 1:3 video predicts like 9:16); excerpt lines cap at 3; `place` puts 3 tall + 3 flat cards into 2 columns with heights differing by less than one tall card; `place` with `start` continues (a new card goes to the shorter existing column); one column keeps date order; `spanFor` rounds up.
- [ ] Run `pnpm nx test web -- masonry` → fail, implement, pass. Commit.

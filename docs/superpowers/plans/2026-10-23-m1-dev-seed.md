## Decisions taken while planning

- **The Job's login is a dev-only system user, `dev_seed` (EDITOR), not a `service` record.** The
  seed writes every content table (stories as their people, reviews as a moderator, the read
  model, tags, fixture people). As a `service` it would need a new clause in about ten table and
  field permissions plus the A2 `processing` rule: a large schema change that only dev uses. A
  system user skips table permissions but not events, so the dataset still passes every rule
  (types and shapes, text limits, approval gate, read-model mirror). The cost: an EDITOR can
  `REMOVE EVENT` (why D13 removed the old per-service users). Accepted: it exists only in dev,
  which holds only dummy data, and every migration re-applies the full schema.
- **Created by SurrealDB's startup init, dev only.** `init.surql.tmpl` gets a `-- @dev-seed-login`
  line. `modules/db-identity` replaces it with `DEFINE USER OVERWRITE dev_seed … ROLES EDITOR`
  (password via ESO from `surreal-dev-seed-password`) when `dev_seed_login` is on, and with
  `REMOVE USER IF EXISTS dev_seed` otherwise. The identity-check sidecar reads the extra user from
  `system-users.json`; the migrate Job's `MIGRATE_EXPECT_USERS` gains it (`modules/db-migration`).
- **Three locks, like D48 (A4):** `modules/cluster` (GCP project heisreal-dev), `modules/gcp`
  (`dev_seed`, project heisreal-dev) and `modules/db-identity` (environment dev). The program
  refuses unless its settings say dev, and the reset (one transaction) refuses unless
  `_setting:consent` says dev with consent relaxed.
- **Media live in Bunny, not git.** The spec (sizes, lengths, labels, fake GPS) and the generator
  are committed; the ~4 MB of files aren't. A developer uploads them once (`upload-media`, which
  finds each by name and uploads only what's missing) and commits `bunny-media.json` (Bunny's
  video ids and encode results; no keys). The Job never talks to Bunny, so it needs no Bunny key.
- **`ci-dev-seeder` (bootstrap, applied locally)** may only start and watch the `dev-seed` Job:
  `roles/run.jobsExecutor` (no overrides) and `roles/run.viewer` on that Job, granted by the gcp
  root. Its WIF gate allows only `reset-dev-data.yml` and `dev-behavioural-tests.yml` dispatched
  on `main`. The test job has no identity.
- **A local composite action, not a reusable workflow,** for the reset: both workflows share one
  concurrency group (`dev-data`), which a called workflow can't share with its caller.
- **0003 retired:** dev stops passing `seed_dev_story` (the cluster module drops the variable);
  the reset deletes 0003's story; its user, consent rows and fixture DPA stay (append-only,
  immutable). The slug `test-story-walking-skeleton` stays, now a dataset story (no longer featured: Joel, 2026-10-23, no featured stories).

## Tasks

1. `apps/dev-seed` (Nx app like `workflow`, built by Release Images): dataset, plan (checks the
   dataset against the schema's limits before connecting), the reset transaction, config guard,
   entrypoint. Unit tests (`dataset.spec.ts`: D47 coverage; `plan.spec.ts`; `config.spec.ts`).
2. Integration test on SurrealDB 3.2.4 (`apps/dev-seed/integration`): loads the dataset as
   `dev_seed`, idempotent, one transaction, keeps non-fixture people, refuses outside dev.
3. Media: `generate-media` (ffmpeg, EXIF GPS writer), `upload-media` (Bunny Stream + Edge
   Storage), with unit tests on fakes. Never run against Bunny in this PR.
4. Identity: init line, identity check, `db-identity` and `db-migration` inputs, tftests;
   `libs/database` integration test for the login (created, checked, removed).
5. OpenTofu: `modules/gcp/dev_seed.tf`, `modules/cluster` switch and tftest, live roots
   (`dev_seed`, `dev_seed_login`, `dev_consent_relaxed = true`), bootstrap identity and gate test.
6. Workflows: `reset-dev-data.yml`, `dev-behavioural-tests.yml`, `.github/actions/dev-seed`;
   `dev-seed` added to the image lists. Behavioural suite: `apps/dev-seed/behavioural`.
7. Docs: app README, OpenTofu and SurrealDB READMEs, db-permissions, delivery status.

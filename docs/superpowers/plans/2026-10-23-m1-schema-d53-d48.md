# M1 step 3: schema changes for D53 (story types and shapes) and D48 (dev-only relaxed consent)

Source: `project/context/research/m1-dev-data-decisions.html` (D48, D53; context D41, D46, D47,
D49, D52). Monorepo docs win where they differ. Out of scope: the dev-seed Job (step 4, D49),
turning the flag on (step 4), UI beyond the footer note, applying anything to cloud.

## Findings that shape the design (SurrealDB 3.2.4, probed before planning)

- **A `DEFINE PARAM` can be shadowed by the caller.** `RETURN fn::x()` where `fn::x` reads
  `$relaxed` returns the caller's bound `$relaxed`, not the defined param. So the D48 switch can't
  be a `DEFINE PARAM`: a person could bind `relaxed: true`. It lives in a row instead:
  `_setting:consent`, readable by everyone, writable by nobody but system users (the migrator).
- **`schema.surql` is DDL only** (the runner's grammar), so the row is written by the runner
  itself in the schema step's transaction (like it already chooses Clerk access vs `REMOVE`).
- **`REMOVE FIELD` doesn't remove stored values, and `array<object>` items accept unknown keys**
  (`media[*]` with an undefined key is stored). So removing `aspectRatio` needs (a) an explicit
  key allow-list check on media items and (b) a data script for rows written before.

## D53 tasks

1. **Integration tests first** (`libs/database/integration/story-shape.int-spec.ts`): every
   allowed and refused combination, on create and on update, by the person and by workflow:
   - written: body required and non-blank; no media; optional image; image ratio limits;
   - video/audio: at most one media item while editable (`draft`, `changes_requested`: the
     contract creates the draft before the upload), exactly one of its own format from submit on;
     body optional; no image;
   - width/height positive ints, both or neither, refused beyond 1:3 / 3:1 (1:3 and 3:1 pass);
     audio has no width/height; unknown media/image keys (e.g. `aspectRatio`) refused;
   - image fields written by the person only (api-admin and workflow writes dropped, D41);
   - `publicStory` mirrors `image` and media `width`/`height`, and refuses extra keys.
2. **Schema** (`schema.surql`): `media[*].width/height` replace `aspectRatio` (with
   `REMOVE FIELD IF EXISTS`), `story.image {path, width, height, alt}` with person-only field
   permissions, `fn::story::shape_problem($s)` (one definition, used by the event and by 0004),
   event `story_shape`, `fn::story::content` includes `image` (content lock + consent), the same
   fields on `publicStory`, the mirror event compares them.
3. **Data script `0004-story-shapes.surql`**: strips leftover `aspectRatio` keys from `story` and
   `publicStory` media and fails the migration if any existing story breaks the new rules
   (dev holds only the 0003 seed, which is valid: written, body, no media).
4. **Contracts**: `MediaPlayback.width/height` replace `aspectRatio`; new `StoryImage`
   (`url`, `width`, `height`, `alt`); `image` on `StoryPublic`, `StorySummary`, `StoryMine`;
   `StorySummary.thumbnailWidth/Height`. Lint with Redocly.
5. **api-public-read** mapper + unit/integration tests: width/height, image (URL `null` until
   D52 token auth, like media URLs today; alt `null` when not given).
6. **web** `public-stories.ts`: types and guard for `image`/`media`, a neutral default alt text,
   and a shared `clampAspect` helper (9:16..2:1) with unit tests (no UI).
7. **0003** stays byte-identical (its checksum is in dev's `_migration` ledger; it's valid under
   the new rules). Harness `approve()` and `write-scope` tests move to width/height.
8. **Docs**: `docs/db-permissions.md` (write scope, mirror, claims table, tables list).

## D48 tasks

1. **OpenTofu**: `variable "dev_consent_relaxed"` (bool, default false) declared only in
   `live/dev/cluster`, passed through `modules/cluster` to `modules/db-migration`. The modules'
   validation refuses `true` unless the environment is dev: `modules/cluster` derives it from
   the verified GCP project (`surrealdb_expected_settings.GCP_PROJECT`, already checked against
   the overlay and the gcp root), `modules/db-migration` takes `environment` and refuses
   `true` for anything but `"dev"`. params.json gains `dev_consent_relaxed` and `environment`.
   `tofu test` (db-migration): default off; on in dev; refused in prod/unset.
2. **Runner** (`migrate.py`): in the schema step, `UPSERT _setting:consent` from the params
   (absent = off); summary and log say whether it's on.
3. **Schema**: `_setting` table (select FULL, writes none), event refusing
   `devConsentRelaxed = true` unless `environment = 'dev'`, `fn::consent::relaxed()`, and
   `fn::consent::granted` returns true for an existing user when relaxed. Everything that
   checks consent (table permission, events, the read-model mirror, `ConsentChecker`/the guard)
   goes through `fn::consent::granted`, so one switch.
4. **Integration tests** (`dev-consent.int-spec.ts`): off by default (every other suite runs off);
   on with environment dev, story create/submit/approve/publish without consent rows; refused
   with another environment; no service or person can write `_setting` or shadow it with a
   bound variable; the ledger itself (`fn::consent::current`) is unchanged.
5. **Apps**: `readConsentRelaxed()` in `libs/database`; `ConsentModule` (api-user, api-admin)
   logs a warning at startup when on; `GET /health` reports `consentChecksRelaxed` (contract
   `Health`); web reads it from api-public-read's `/health` (server-side, cached 60 s) and shows
   the footer note "consent checks relaxed (dev)". Unit tests for each.
6. **Docs**: delivery-status (D48/D53 progress, changelog), db-permissions.
